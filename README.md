# Отбор признаков для бустинга: от 100 к 30

Учебный пример к лекции «Как делают бустинги: промышленная практика».

* `data/scoring_1000x100.csv` — выдуманный датасет кредитного скоринга: 1000 строк, 100 признаков,
  служебные столбцы `client_id`, `report_month` (январь–декабрь 2025), `target` (дефолт).
* `feature_selection.ipynb` — ноутбук, который проходит маршрут отбора и оставляет 30 признаков.
  Сохранён с выполненными ячейками: результаты видны прямо на GitHub.
* `make_dataset.py` — генератор датасета (воспроизводимый, `seed=2025`).
* `selected_30_features.csv` — итоговый список признаков.

## Маршрут отбора

0. Модель на всех признаках — точка отсчёта.
1. Убираем признаки с нулевой важностью (пустые и константные).
2. PSI по кварталам и ручной бан красных (PSI > 0,25).
3. Backward по важности пачками до 45 признаков.
4. Корреляции > 0,7: из пары убираем тот, без которого Gini на val выше.
5. Backward по Gini до 30 признаков.

Измерение: OOT — октябрь–декабрь 2025; test — 20 % клиентов из остальных месяцев;
train — 5 фолдов по клиентам (`StratifiedGroupKFold`), решения принимаются по Gini на val.

## Что спрятано в данных

* Шесть признаков с высоким PSI, которые мешают (`gambling_spend_3m`, `crypto_transfers_1m`,
  `hotline_calls_30d`, `cash_withdrawal_share_1m`, `microloan_apps_90d`, `night_txn_share_1m`):
  до октября они сильнее всех предсказывают дефолт, в OOT их распределение уезжает,
  а связь с таргетом пропадает. С ними Gini на val выше, а на OOT модель проваливается.
* Два нестабильных признака без связи с таргетом (`promo_offer_cnt_1m`, `app_version_code`).
* Пять пустых или константных признаков.
* Пары сильно коррелированных признаков (`dpd_max_6m` / `dpd_max_12m`, `salary_inflow_1m` /
  `salary_inflow_3m` и др.).
* Остальное — правдоподобный шум.
